8 Accessibility Issues

1
Unlabeled Icon Button — Info (ⓘ)
WCAG 4.1.2 High

The ⓘ icon in the top-right header has no accessible name. VoiceOver and TalkBack will announce it only as "button" — users cannot determine its purpose without sighted context. This is a complete barrier for blind and low-vision users trying to access additional information.

✅ Fix
Add a descriptive label to the button element:
accessibilityLabel="More information about Multichannel Orders"
Web: aria-label="More information about Multichannel Orders"
WCAG 4.1.2 – Name, Role, Value (Level AA)
2
Touch Target Too Small — Info Icon
WCAG 2.5.5 High

The ⓘ info button is approximately 28×28pt — well below the 44×44pt iOS HIG minimum and WCAG 2.5.5's 44×44px requirement. Users with motor impairments, tremors, or low dexterity will frequently miss-tap or be unable to activate it.

✅ Fix
Expand the tap area with padding or a larger container:
style={{ padding: 10 }} brings effective area to ~48×48pt ✓
Or: wrap in a 44×44pt TouchableOpacity with centered icon.
WCAG 2.5.5 – Target Size (Level AA) · Apple HIG: minimum 44×44pt
3
Illustration Missing Text Alternative
WCAG 1.1.1 Medium

The illustration of a person distracted by their phone conveys the "lost / disconnected" metaphor of the error state. Without a text alternative, screen reader users receive no description and miss the contextual meaning. Non-decorative images must have a text alternative.

✅ Fix
If meaningful, add a description:
accessibilityLabel="Illustration of a person distracted by their phone"
If purely decorative: accessibilityHidden={true} (RN) or alt="" (web)
WCAG 1.1.1 – Non-text Content (Level A)
4
Error State Lacks Live Region Announcement
WCAG 4.1.3 Medium

The "Page not found" state appears after a failed navigation — a dynamic content change. Without a live region, VoiceOver and TalkBack won't announce it. Users relying on a screen reader may have no idea the page failed to load unless they manually swipe through content.

✅ Fix
Wrap the error container in a live region:
React Native: accessibilityLiveRegion="assertive"
Web: role="alert" or aria-live="assertive"
WCAG 4.1.3 – Status Messages (Level AA)
5
Ambiguous Button Label: "Retry"
WCAG 2.4.6 Medium

"Retry" is ambiguous when read out of context — screen reader users navigating via a rotor or button list won't know what is being retried. Descriptive labels must convey purpose without relying on surrounding content for context.

✅ Fix
Add a self-describing accessible label:
accessibilityLabel="Retry loading Multichannel Orders"
Or update visible text to: "Try again" with clearer surrounding copy.
WCAG 2.4.6 – Headings and Labels (Level AA) · 2.4.9 Link Purpose (AAA)
6
Active Tab Indicated by Color Alone
WCAG 1.4.1 Low

The "Orders" tab is highlighted in blue (#0071E3) while all others are gray — color is the sole visual indicator of the active state. Users with color blindness (deuteranopia, protanopia) or those on high-contrast / monochrome displays may not perceive which tab is selected.

✅ Fix
Add a non-color indicator: a top/bottom active bar, bold label text, or filled vs. outline icon. Also add programmatic state:
RN: accessibilityState={{ selected: true }}
Web: aria-selected="true" inside a role="tablist"
WCAG 1.4.1 – Use of Color (Level A)
7
Dropdown Trigger Missing ARIA Role & State
WCAG 4.1.2 Low

The "Multichannel Orders ⌄" header trigger has no declared interactive role or expanded/collapsed state. Screen readers may read the chevron as a text character or skip the interactivity entirely, leaving users unaware they can switch channels.

✅ Fix
Declare role and state on the trigger container:
accessibilityRole="button"
accessibilityLabel="Multichannel Orders — switch channel"
accessibilityState={{ expanded: false }}
WCAG 4.1.2 – Name, Role, Value (Level AA)
8
Subtext Contrast Below AA Minimum
WCAG 1.4.3 Low

"This page doesn't seem to exist." appears in iOS system gray (#8E8E93) on white (#FFFFFF). This combination yields a contrast ratio of approximately 3.5:1 — below WCAG AA's 4.5:1 requirement for normal-sized text. Low-vision users and users in bright environments will struggle to read it.

✅ Fix
Darken the subtitle color to meet the minimum:
color: #636366 → ~4.54:1 on white ✓ (just passes AA)
color: #48484A → ~5.9:1 on white ✓ (comfortable margin)
WCAG 1.4.3 – Contrast Minimum (Level AA) · Required ratio: 4.5:1
