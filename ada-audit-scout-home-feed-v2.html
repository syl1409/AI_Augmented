Issues Screen 2 — Home Feed
Fix in Figma before handoff
1
Search placeholder text — insufficient contrast 1.4.3 High 🎨 Design
The search bar placeholder "Search by vibe, area, or feature..." renders at rgba(255,255,255,0.45) (~2.3:1) against the blue #1D3461 header. WCAG requires 4.5:1 for normal text. Users with low vision cannot read the search affordance.
Fix
Increase placeholder opacity to at least rgba(255,255,255,0.72) (~4.6:1). In Figma update the placeholder token from white/45% → white/72%.
WCAG 1.4.3 – Contrast Minimum (AA)
2
Notification bell — touch target too small 2.5.5 Medium 🎨 Design
The notification button is designed at 36×36px. WCAG 2.5.5 requires 44×44px minimum for pointer targets. iOS HIG also mandates 44pt. Users with motor impairments will frequently mis-tap and land on adjacent avatar.
Fix
Increase the component frame in Figma to 44×44px. The visible icon can stay 36px — pad the invisible hit area. Alternatively increase the icon and button to 44px.
WCAG 2.5.5 – Target Size (AA) / iOS HIG 44pt minimum
3
Status badges convey meaning through color alone 1.4.1 High 🎨 Design
The "Photos clean" (green), "Seller urgent" (pink), and "AI flag" (red) badges in the property cards use only color to signal meaning. Users who are color-blind or using grayscale display cannot distinguish "Seller urgent" from "Photos clean".
Fix
Each badge already has an emoji (✓, ↑, ⚠️) — good start. Ensure the emoji is never removed in edge cases. Add a distinct text prefix per type in the design spec (e.g. "Good · Photos clean", "Alert · Seller urgent") or use distinct icon shapes rather than relying only on emoji color.
WCAG 1.4.1 – Use of Color (A)
4
No focus ring style defined for interactive elements 2.4.7 Medium 🎨 Design
The design system defines no `:focus-visible` state for chips, property cards, nav items, or buttons. Without a designed focus ring, developers default to the browser outline (inconsistent) or remove it entirely. Keyboard and switch-access users cannot see where they are on screen.
Fix
Add a Focus/Selected variant to every interactive component in Figma: outline: 3px solid #E91E8C; outline-offset: 2px (use the Brand/Pink token). Document it in the design system page.
WCAG 2.4.7 – Focus Visible (AA)
5
Match score pill — low contrast on photo overlay 1.4.3 Low 🎨 Design
The "92 Match" pill sits over the dark gradient overlay on the property photo. White text on the pink (#E91E8C) pill reads at ~3.9:1 — below 4.5:1 for normal-weight text at 11px. Slightly smaller or thinner type will fail.
Fix
Use #CC0F75 (Brand/Pink Mid) for the pill background instead of #E91E8C, giving white text a 4.8:1 ratio. Or use font-weight: 800 (large bold text, 3:1 threshold).
WCAG 1.4.3 – Contrast Minimum (AA)
Fix in code during implementation
6
Live alert strip not announced to screen readers 4.1.3 High 💻 Dev
The "2 new matches in 78701" strip updates dynamically when new listings arrive, but lacks role="status" or aria-live. VoiceOver/TalkBack users will never hear this real-time alert — defeating the core JTBD J1 (be first to know) for blind users.
Fix
<div role="status" aria-live="polite" aria-atomic="true"> on the alert strip. Use aria-live="assertive" if the alert is time-critical (a new listing appearing in a competitive market typically is).
WCAG 4.1.3 – Status Messages (AA)
7
Avatar button has no accessible name 1.1.1 High 💻 Dev
The "MC" avatar renders as a decorative div without a button role or label. Screen readers announce it as unlabeled interactive element (or skip it). "MC" has no context — is it a menu, profile link, or logout button?
Fix
<button aria-label="Maya Chen — open profile menu">MC</button>. Use aria-label not title — title is not reliably announced on mobile screen readers.
WCAG 1.1.1 – Non-text Content (A) + WCAG 4.1.2 – Name, Role, Value (A)
8
Filter chips have no accessible role or grouping 4.1.2 High 💻 Dev
The filter chips (All matches / Just listed / Price cut / Near me) are <div> elements. They behave as a single-select radio group but have no role, no keyboard interaction, and no announcement of selected state. Screen reader users cannot operate the filter.
Fix
Wrap in <div role="radiogroup" aria-label="Filter listings">. Each chip: <button role="radio" aria-checked="true/false">. Active chip: aria-checked="true". Handle arrow-key navigation per ARIA radio group pattern.
WCAG 4.1.2 – Name, Role, Value (A)
9
Notification badge "2" has no text alternative 1.1.1 Medium 💻 Dev
The red badge showing "2" on the Alerts nav item and notification bell is a styled div. Screen readers read it as "2" without context — "2 what?" Blind users miss that there are 2 unread alerts.
Fix
On the nav bell: <button aria-label="Notifications, 2 unread">. Hide the visual badge from screen readers: <span aria-hidden="true">2</span> and add a visually-hidden sibling: <span class="sr-only">, 2 unread</span>.
WCAG 1.1.1 – Non-text Content (A)
10
Heart/save buttons lack property context in accessible name 2.4.6 Medium 💻 Dev
Both save buttons announce as "🤍" (or "white heart"). Without the property address in the label, a screen reader user navigating by buttons hears "Heart, Heart" and cannot distinguish which listing they're saving.
Fix
<button aria-label="Save 1847 Cedar Hills Blvd" aria-pressed="false">. Toggle to aria-label="Unsave 1847 Cedar Hills Blvd" and aria-pressed="true" when saved. The emoji content can stay; add aria-hidden="true" to the emoji span.
WCAG 2.4.6 – Headings and Labels (AA) + WCAG 4.1.2 – Name, Role, Value (A)
11
Bottom nav active item missing aria-current 4.1.2 Low 💻 Dev
The "Home" tab is visually active (pink color + underline) but has no aria-current="page". Screen readers cannot tell which tab is currently selected without audible confirmation — users may double-navigate trying to find where they are.
Fix
Add aria-current="page" to the active nav item. In React/Vue, bind it dynamically: aria-current={currentRoute === 'home' ? 'page' : undefined}. Wrap the nav in <nav aria-label="Main navigation">.
WCAG 4.1.2 – Name, Role, Value (A)
